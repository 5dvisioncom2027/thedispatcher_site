Проблема найдена: роль `admin` у пользователя `admin@admin.com` есть, но запрос роли падает с ошибкой доступа к функции `has_role`. Из-за этого фронтенд получает пустой результат и показывает “Your account has no admin role”.

План исправления:

1. Исправить права в backend/database
   - Добавить `GRANT EXECUTE` для функции `public.has_role(uuid, app_role)` роли `authenticated`.
   - Оставить функцию закрытой для anonymous/public пользователей.
   - Не менять модель ролей и не хранить admin на профиле.

2. Сделать проверку admin устойчивее в UI
   - В `/admin` явно обрабатывать ошибку запроса роли.
   - Не показывать “no admin role”, если на самом деле произошла backend permission error.
   - Показывать понятное сообщение о проблеме доступа, если роль не удалось проверить.

3. Исправить кнопку Admin в шапке
   - Сейчас шапка тоже читает `user_roles`; после исправления прав она начнет видеть admin.
   - Добавить безопасную обработку ошибки, чтобы не скрывать admin без причины при сбое запроса.

4. Проверить результат
   - Убедиться, что `admin@admin.com` действительно имеет роль `admin`.
   - Проверить, что `/admin` открывает админ-панель после обновления страницы.

Технически это будет небольшая database migration + небольшое изменение проверки ролей в `SiteHeader` и `src/routes/_authenticated/admin.tsx`.
